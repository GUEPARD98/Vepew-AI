📋 Informe Técnico VPEW-AI
✅ Puntos Fuertes

Arquitectura clara: agente real con recolección de procesos y conexiones, análisis híbrido (reglas + ML), logging a archivo y Event Log, estadísticas de operación.

Buenas prácticas operacionales: rutas en C:\ProgramData\vpew-ai, rotulado de amenazas, control por CLI con ciclo único o continuo, métricas para evaluar rendimiento.

ML desacoplado: paquete propio con simple models (sklearn) y un Trainer capaz de sintetizar datos para bootstrap rápido.

❌ Problemas Bloqueantes (ejecución)

Incompatibilidad de interfaz ML en vpew_real.py

Se invoca predict(features) como si aceptara lista de 25 floats y devolviera float + dict.

En realidad, los modelos simples esperan DataFrame y retornan listas/arrays, no dicts.

Impacto: excepciones en runtime.

Nombres de modelos inconsistentes

vpew_real.py busca .keras.

Los simples usan .joblib.

Impacto: modelos nunca cargan, se fuerzan reentrenamientos.

Firma de Trainer incorrecta

Se llama train_all_models(epochs=10).

Firma real no acepta epochs.

Impacto: excepción y ML desactivado.

Salida del clasificador mal usada

Se espera dict {class, confidence, probabilities}.

SimpleThreatClassifier.predict retorna lista de etiquetas, predict_proba matriz.

Impacto: errores al acceder a claves inexistentes.

⚠️ Hallazgos de Calidad/Diseño (no bloqueantes)

Detección de IP interna incompleta → solo 172.16, falta todo 172.16/12, 10/8, 192.168/16.

Puertos sospechosos incluyen 8080/8443 → riesgo de falsos positivos.

Ubicaciones system32/syswow64 → legítimas, requieren contexto extra.

Event Log → fuente no registrada puede fallar, aunque ya hay try/except.

Logs de psutil → demasiado verbosos bajo excepciones.

Entropía en cmdline → umbral 4.5 puede generar falsos positivos.

Métrica detection_rate poco representativa en primeros ciclos.

Intervalo fijo (30s) en modo continuo → no se adapta realmente a amenazas críticas.

🛠 Recomendaciones Prioritarias

Alinear interfaz ML

Generar DataFrame con columnas feature_0..feature_24.

Anomalías: usar predict(df) o score_samples.

Clasificación: usar predict(df) + predict_proba(df).

Derivar confidence = max(probabilidades).

Unificar nombres de modelos

Usar *.joblib en carga/guardado.

Ejemplo: models/anomaly_detector.joblib.

Corregir Trainer

Quitar epochs en train_all_models.

Si se requiere parametrizar, extender firma sin romper compatibilidad.

Afinar análisis de red y procesos

Usar ipaddress para redes privadas/loopback.

Reducir falsos positivos en puertos y paths.

Detectar patrones PowerShell (-enc, -EncodedCommand).

Mejorar Event Log y logging

Registrar fuente o usar Application preexistente.

Mantener fallback a log de archivo.

Optimizar operativa

Añadir listas blancas configurables.

Reutilizar scaler/estado de modelos guardados.

Considerar ETW/Sysmon a futuro.

🎯 Impacto Esperado

Evita fallos en ML y activa análisis híbrido real.

Reduce falsos positivos en red y procesos.

Aumenta coherencia y mantenibilidad entre módulos.

Mejora operativa sin cambios radicales de arquitectura.
